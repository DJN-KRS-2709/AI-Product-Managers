## The four pillars (user-flow.md)

The AI Iceberg model. Specify each pillar with both an **underwater** half (logic) and a **surface** half (what the user sees):

1. **The Trigger** — earliest possible signal that starts the flow.
2. **The Processing State** — hidden logic + handshake breadcrumbs that build trust during the wait.
3. **The Presentation** — placement maneuver (Inline / Floating / Full-Page) that wraps the value prop.
4. **The Feedback Loop** — kill switch + training signal + fail-safe path.

## The three gaps (trust-gaps.md, optional)

- **Black-box gap** — can the user see *why* the AI decided?
- **Hallucination gap** — could this confidently be wrong?
- **Control gap** — can the user steer or stop?

Plus the **Intelligence Tax** — is the latency / privacy / cognitive load worth the value?

## Self-review checklist (M4)

- [ ] Trigger fires on the earliest possible signal — no manual "Start AI" click.
- [ ] At least one breadcrumb message turns latency into transparency.
- [ ] Maneuver matches the M2 value prop (Automation / Augmentation / Insights / Personalization).
- [ ] Every automated decision has a working kill switch.
- [ ] Fail-safe path is explicit. No dead end with a bad AI result.
- [ ] Hidden logic references M3 PRD specs (Top-K, latency target, knowledge base).
- [ ] If you ran the post-class lab: every closed gap (Black-box / Hallucination / Control) has a verifiable UI change in the Lovable prototype.
