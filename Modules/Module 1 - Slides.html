Provocation

Prompting is product configuration —
not chatting.

Thumb-vote each line — then we unpack with real teams.
FALSE
"Prompts are throwaway — eng will rewrite them."
Production AI products ship with versioned, evaled prompts. OpenAI, Notion AI, Linear — system prompts are the product surface.
FALSE
"If the model is good enough, the prompt doesn't matter."
Same model, different prompt = different product. GitHub Copilot vs Cursor use the same base — the prompt is the moat.
TRUE
"Most PMs ship prompts that drift on day 2."
Without anatomy + refusal rules + evals, prompts collapse the moment a user types something off-pattern.

Lecture

Why this is hard

Same input. Two different outputs. Welcome to product variance.
Deterministic
Same input → same output.
SQL, regex, every API you've shipped before. Specs assume the system behaves.
Non-Deterministic
Same input → variable output.
Every modern LLM, every agent. Specs must shape behaviour and measure it.

Your job: narrow the variance. Configuration · guardrails · evals.

Framework

Anatomy of a High-Quality Prompt

Five elements every production prompt declares.
①
Context
Who the AI is, what system it lives in, what it knows.
②
Task
The explicit instruction (verb-first).
③
Constraints
Must-not-do, format, scope. At least three.
④
Output Format
Schema, length, structure.
⑤
Examples
1–3 ideal pairs, when format matters.

If any element is missing, your output drifts on day 2.

Framework

Prompting as Configuration

Once you treat the prompt as configuration, every framework becomes obvious.
TechniqueUse whenExample for Juno
Zero-shotThe model already knows the domain. Behaviour needs tuning, not knowledge."Summarise these 12 escalations in 3 bullets."
Few-shotYou need a specific format or style — show 1–3 examples.Two ideal P0 spec templates as reference.
Chain-of-thoughtMulti-step reasoning required.Risk prioritisation: "Think step-by-step before ranking."
System prompt + rolePersona, persistent guardrails, organisation context."You are Juno, an Associate PM. You never execute, only flag."

The technique you pick is a product decision, not a prompt-engineering trick.

Speaker Notes

Tie each row to a Juno scenario. Few-shot for spec generation. Chain-of-thought for prioritisation. System prompt for persistent role.

Lecture

The Two Dials PMs Should Know

Top-p, frequency penalty, presence penalty — nice to know, not must-know.
Temperature
0 = deterministic-ish · 1+ = creative.
Spec it for the job. Risk-watchdog Juno = low. Brainstorming Juno = high. PMs decide this — not engineers.
Max Tokens / Length
Cap it.
Long outputs hide failures. Short outputs force prioritisation. Most consumer LLMs default too long.

The point is awareness, not mastery. Know temperature exists. Know it's a product decision.

Framework

The Optimisation Decision Framework

Three levers. Cheapest first. If prompt fixes it, don't build infra.
LeverTry whenCost / time
PromptModel already knows the domain. Behaviour needs tuning, not knowledge.Minutes. Almost free.
RAGNeed to ground the model in your data. (M3 lives here.)Days. Real infra cost.
Fine-tuneStyle/format/behaviour matters more than retrieval. Last resort.Weeks. Real infra + training cost.

If you can fix it with the prompt, do not build infra.

Seed Prompt

The Juno PM Seed Prompt

Build a web app called "Juno PM". It is the homepage for an AI Associate PM that lives inside Slack, Notion, and Jira. The homepage has:
- A hero strip with the tagline "Scale your judgment, not yourself"
- A three-column section explaining the pillars: Synthesize Insights, Draft Specs, Prioritize Risks

Key Takeaways

Drive AI-First Execution with Prompting

Prompting is configuration, not chat. The prompt is a product surface — versioned, evaled, reviewed.

Five elements or it drifts. Context · task · constraints · output · examples. Drop one, the output collapses.

Cheapest lever first. Prompt → RAG → fine-tune. Don't build infra to fix something the prompt would solve.

Prototype to feel the speed. Lovable + a seed prompt = a working surface in 25 minutes.

The repo is the throughline. By M6 you commit four artifacts: PRD · system prompt · data + retrieval · eval set.
