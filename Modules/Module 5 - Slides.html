Section 01
The Shift to Agentic Orchestration

Speaker Notes

Section 1 — from answers to judgement. The dynamic between user and product changes when the system gains judgement.

Lecture · Frame

From answers to judgement

This changes the dynamic between your user and your product — you now design for goals and guardrails, not turns and replies.
01
Chatbot
Value prop

Provide answers based on a knowledge base.

Operating model

Reactive: System responds only when prompted; user owns the workflow.

02
Workflows
Value prop

Provide execution of predefined steps across systems.

Operating model

Human-supervised: System follows a rigid track; human monitors the process.

03
Agents
Value prop

Provide judgement for path choice based on real-time context.

Operating model

Autonomous: System chooses the next step; human sets the goal and the guardrails.

PM lens: when the system gains judgement, your spec stops describing outputs and starts describing rules of action.

Speaker Notes

Source slide 7. Chatbot → Workflows → Agents. The PM job shifts from spec'ing outputs to spec'ing rules of action.

Lecture · Definition

What is an agent?

An agent is an intelligent system that interprets intent, makes decisions, and takes actions autonomously to achieve a goal. Unlike standard models, agents act on their environment, not just on prompts.

1
🚀
Proactive

Acts on environmental triggers without direct user prompts or input.

2
🎯
Task-Oriented

Executes multi-step workflows to deliver finished outcomes.

3
🔗
Integrated

Connects with tool stacks to perform actions in the real world.

Speaker Notes

Source slide 8. Definition + the three traits (Proactive / Task-Oriented / Integrated). If a system has all three, it's an agent — otherwise it's a tool or assistant.

Lecture · Mental model

The anatomy of an agent

Three layers + a brain. Memory carries context, the brain decides, tools act.

PM read: the Strategy + Action layers are your spec. The brain ships with the model. The PM is responsible for everything around it.

Speaker Notes

Source slide 9. The Brain (LLM) + Reasoning Engine + Strategy Layer + Action Layer. PM owns Strategy and Action; the Brain ships with the model.

Framework

The Agent Spectrum

More autonomy means assuming a higher level of operational accountability.
0
Reactive
(No Autonomy)

PM owns the prompt quality and response accuracy.

1
Function-Calling
(Assisted Autonomy)

PM owns tool selection logic and fallback behaviors.

2
Semi-Autonomous
(Human-in-the-Loop)

PM owns checkpoint design and approval thresholds.

3
Fully Autonomous
(Goal-Driven)

PM owns the full guardrail spec, eval suite, and kill switch.

PM rule of thumb: ship the lowest level that delivers the job. Higher levels need explicit handoff rules and a real eval surface.

Speaker Notes

Source slide 10. Four levels (Reactive → Function-Calling → Semi-Autonomous → Fully Autonomous). PM accountability rises with autonomy.

Section 02
Agentic Design Patterns

Speaker Notes

Section 2 — pick the wiring before you write the prompt. Pattern is spec.

Lecture · Frame
Why patterns matter

Designing for outcomes

You don’t solve complex agentic problems with a better prompt. You solve them by choosing how the agent is wired to think.

1
Patterns provide a common vocabulary

Define expected AI output behaviors in your AI PRD — so engineering and PM agree on how the agent thinks, not just what it returns.

2
Patterns enforce a reasoning structure

They prevent orchestration-gap failures like reasoning drift and infinite loops. The wiring choice is the spec.

Speaker Notes

Source slide 13. Patterns provide a common vocabulary + enforce a reasoning structure. They prevent orchestration-gap failures (drift, infinite loops).

Agentic Pattern · 1 of 2

ReAct — the agent that thinks before it acts

A continuous Reason → Act → Observe loop verifies logic against real-world data before delivering the final answer.
⚙️ Mechanism

A Reason → Act → Observe loop verifies the agent’s logic against real-world data before delivering the final response.

💡 Value

Solves high-variability problems by “thinking out loud” — producing a visible reasoning trace for easier debugging.

⚠️ Cost

Every loop adds latency and tokens. Bound the loop with a max_steps ceiling.

Speaker Notes

Source slide 14. ReAct pattern — Reason → Act → Observe loop. Best for bounded sequential tasks with feedback loops. Default pattern for most PM use cases.

Agentic Pattern · 2 of 2

Planner-Executor — the agent that maps its own roadmap

A planner agent decomposes the goal. One or many executor agents run the steps. The planner re-plans on failure.
⚙️ Mechanism

Planner decomposes & sequences. Executor(s) run, report, escalate.

💡 Value

Best for multi-step tasks with parallelism — the planner can fork executors.

⚠️ Cost

Two surfaces to debug. Spec the handoff contract crisply.

Speaker Notes

Source slide 15. Planner-Executor — one planner agent decomposes; one or many executor agents run. Best for multi-step tasks with parallelism.

Framework

Types of agentic memory

Just like humans have different ways of remembering, agents leverage distinct memory types for different purposes.

1
Episodic
Within one run

Track the sequence of actions taken within a specific multi-step task.

2
Semantic
Across sessions

Store persistent behaviours, user preferences, and core system instructions.

3
Working / Contextual
Live, in-flight

Manage the immediate data and variables currently being processed.

4
External Tools
Source of truth

Access real-world systems and live databases via persistent APIs.

PM rule: spec each memory type explicitly — including the “no’s.” “Juno does not maintain long-term memory of customer-specific contracts” is a spec line worth writing.

Speaker Notes

Source slide 16. Four memory types: Episodic, Semantic, Working/Contextual, External Tools. PM rule: spec each one explicitly — including the no's.

Section 03
Managing the Agentic Handoff

Speaker Notes

Section 3 — the PM job: define the rules of engagement. AWSpec, Control Panel, Decision Triangle.

Framework
One-page blueprint

The Agent Workflow Spec (AWSpec)

Your technical bridge for translating a high-level agentic feature into a structured, governable design that engineering can actually build — and that you can measure.

1
Actors
Who is in the loop?

Define which agents, tools, and humans are involved in the loop. Be explicit about who is the pilot driving the goal and exactly when control passes back.

2
Pattern Plan
Which wiring + steps?

Identify which core agentic pattern(s) will be used. Map the key sequential steps the agent must take to transform the initial goal into outcomes.

3
Memory
What persists, where?

Specify what information must persist across the session and define the scope. Determine what needs to be in working memory versus what can be retrieved.

4
Tools
Which APIs, what scope?

List the specific APIs and internal databases the agent is authorized to call. Define the required schemas and read / write boundaries.

Common failure modes

The Orchestration Gap

When patterns fail, they fail in predictable shapes. Spec defences for each.
💤
Silent Failures

When a tool returns “No data,” the agent may falsely assume the task is complete instead of verifying the query logic.

tool: search('Q1 churn cohort')
→ result: []
→ agent: "Task complete." ✓
🌀
Reasoning Drift

After multiple loops, the agent can lose its “North Star” and begin autonomously solving for the wrong sub-task.

step 1: synthesise risks
step 2: prioritise risks
step 6: ...explain methodology
♻️
Infinite Loops

The agent gets stuck in a thought-action cycle, repeatedly trying a failing tool without recognising a logical dead end.

Think → Act → Observe (fail)
Think → Act → Observe (fail)
Think → Act → Observe (fail)…
⏱️
The Latency Tax

Each autonomous reasoning step adds cumulative seconds; a 5-step loop can force a user to wait 40+ seconds for a result.

step 1 (8s)  step 2 (7s)
step 3 (12s) step 4 (6s)
step 5 (9s) → total: 42s

Speaker Notes

Source slide 22. Four common failure modes — Silent Failures, Reasoning Drift, Infinite Loops, Latency Tax. Each fails in a predictable shape; spec defences for each.

Framework
From logic to control

A PM’s Agent Control Panel

Four levers you specify. Engineering implements. You measure.
1
Define Stop Conditions

Set the number of max_steps to prevent infinite loops and cost overruns.

2
Structure Tool Outputs

Partner with engineering to ensure APIs return clear observations and avoid hallucinations.

3
Set Confidence Thresholds

Define when an agent’s thoughts trigger human-in-the-loop reviews.

4
Manage the North Star

Provide the system instructions an agent re-reads in every loop to prevent reasoning drift.

Speaker Notes

Source slide 23. PM's Agent Control Panel: Stop Conditions, Tool Outputs, Confidence Thresholds, North Star instructions. Four levers PM specifies; engineering implements.

Framework

Defining the rules of engagement

Four contracts the PM owns — one per axis of risk.
🔐
Agency Permission

You define the autonomy threshold.

e.g.

An agent can draft a $5k quote but cannot hit “Send.”

🔑
Access Control

You identify the read/write boundaries for every tool and database.

e.g.

The agent can read the HR handbook but cannot edit payroll.

↩️
Fallback Protocols

You specify the fallback experience when loops break or gates are triggered.

e.g.

After 3 failed attempts to resolve, the agent must escalate to a human.

🚨
Checkpoints

You set the red-zone triggers for human intervention based on risk, value, or ambiguity.

e.g.

Any legal-policy change by an agent requires a human approval step.

Speaker Notes

Source slide 24. Four rules of engagement: Agency Permission, Access Control, Fallback Protocols, Checkpoints. The PM contract for risk per axis.

Framework
Balancing trade-offs

The PM Decision Triangle

Three axes. Pick two to optimise — the third pays the bill.

PM rule: name the corner you’re sacrificing in the AWSpec. “We are buying accuracy at the cost of latency” is a defensible decision. Silence isn’t.

Speaker Notes

Key Takeaways

Deploy Agentic Systems and Workflows

From manual prompting to governing agents. PMs shift from prompt craft to defining the rules under which an agent exercises judgement on real-time context.

Agent anatomy = strategy + action layers. The reasoning engine and strategy layer deconstruct goals into multi-step plans. PMs oversee the underwater wiring.

Patterns replace if-then rules. ReAct, Planner-Executor, and friends provide scalable, resilient reasoning. Pick the lowest-cost pattern that delivers.

PMs define the rules of engagement. Stop conditions, access boundaries, and human-in-the-loop checkpoints. The AWSpec is the contract.
