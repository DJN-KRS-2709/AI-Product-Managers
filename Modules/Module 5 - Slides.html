The Shift to Agentic Orchestration

From chat → autonomous task execution

Year 1 of GenAI: chat boxes. Year 2: copilots. Year 3 (now): agents that do work.

  • Chat: model generates text. Human acts.
  • Copilot: model drafts, human approves, human acts.
  • Agent: model plans, calls tools, observes results, iterates. Model acts.

Speaker Notes

The big shift is "model acts." Up until now we've spec'd outputs. Now we spec rules of action.
What is an agent?

Key traits of agency

Goals

Pursues a goal, not just responds.

Tool use

Calls functions on the world.

Memory

State persists across turns or sessions.

Iteration

Observes results, re-plans.

If a system has all four, it's an agent. If it has one or two, it's a tool or assistant.

Speaker Notes

The four-trait test is more useful than the agent spectrum for spec work. Use it to pressure-test "agentic" claims.
The Agent Spectrum

Tool → Assistant → Agent → Autonomous Agent

LevelBehaviourJuno example
ToolDoes one thing on request"Summarise this thread"
AssistantDrafts, recommendsJuno suggests 3 risks; PM picks
AgentPlans + calls tools + iteratesJuno triages P0s, opens Jira stubs, posts to #pm-daily
Autonomous AgentOperates long horizons unsupervisedNot appropriate for Juno's risk profile

Pick the lowest level that delivers the job. Higher levels need explicit handoff rules.

Speaker Notes

Most "autonomous agents" you'll see in vendor pitches are actually mid-agents. Don't pay autonomous-agent prices for mid-agent capability.

Speaker Notes

The Hidden Costs of Autonomy

Speed vs. reliability trade-offs

  • Cascading errors — one wrong tool call → next step builds on it.
  • Cost blowup — autonomous loops without stop conditions burn tokens.
  • Audit opacity — "the agent decided" is not an audit log.
  • Drift — long-term memory pulls behaviour off-spec over weeks.

The PM job: make these costs visible and bounded in the spec.

Agentic Design Patterns

ReAct + Planner-Executor

ReAct

Reason → Act → Observe → loop

Single-agent reasoning. Best for bounded, sequential tasks with feedback loops.

Juno triaging one P0 thread.

Planner-Executor

Planner agent decomposes; one or many executors run; planner re-plans on failure.

Best for multi-step tasks with parallelism.

Juno running the full daily risk pipeline across all #escalations.

Speaker Notes

For most PM purposes, ReAct is the workhorse. Planner-Executor enters when you have parallel sub-tasks or when a single agent's context window can't hold the whole plan.
Types of Agentic Memory

Four memory flavours

TypeLifetimeUse for
Short-termWithin one taskTool results, intermediate reasoning
Long-termAcross sessionsUser preferences, learned facts
EpisodicSpecific past events"Last week the user said X"
SemanticGeneral knowledgeOrg context, domain facts

Memory choices shape privacy, cost, and behaviour. Spec each one explicitly.

Speaker Notes

Memory is where most agents go wrong in production. Get learners thinking about *what* they remember, *for whom*, and *for how long*.
Common Failure Modes

Spec for the failure

  • Hallucinated tool calls — the agent invents an API.
  • Memory poisoning — bad data persisted as fact.
  • Runaway loops — no stop condition; cost explosion.
  • Silent handoff failure — should have escalated, didn't.
  • Drift across sessions — long-term memory off-spec.

The AWSpec has explicit handling for each.

Managing the Agentic Handoff

The PM's Agent Control Panel

The levers a PM specs and watches:

  • Triggers — when does the agent activate?
  • Tools — what can it call?
  • Memory scope — what does it remember, for how long?
  • Stop conditions — when does it hand back / shut down?
  • Observability — logs, traces, eval surface (M6).

If any lever is missing, you've shipped a liability.

Agent Workflow Spec (AWSpec)

The rules of engagement

Nine sections. The deliverable for M5.

  1. Goal — one sentence.
  2. Trigger — exact condition.
  3. Inputs — required context.
  4. Tools available — explicit list, with each tool's scope.
  5. Memory — what's stored, where, for how long.
  6. Pattern — ReAct or Planner-Executor (+ why).
  7. Stop conditions — success, failure, escalation, timeout.
  8. Handoff rules — when does Juno hand back to the PM?
  9. Eval hooks — what gets logged for the M6 eval stack.

Self-review checklist

Before you ship the AWSpec

  • Goal is one sentence and names the value frame.
  • Trigger is a precise, testable condition.
  • Tools are listed with scope (read-only? write?).
  • Memory section names each of the 4 types in scope or out.
  • Stop conditions list at least 3 (success, failure, escalation).
  • Handoff rules name a confidence threshold.
The PM Decision Triangle

At every step: AI alone / AI + human / human alone

The triangle is the boundary contract between PM and agent.

AI alone

Full execute. Low risk, high trust earned via evals.

AI + human

Draft + approve. The default for high-risk steps.

Human alone

Agent declines, escalates. For contracts, regulators, novel situations.
