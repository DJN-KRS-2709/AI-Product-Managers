The Anatomy of a High-Quality Prompt

Five elements every production prompt declares

  1. Context — who the AI is, what it knows, what system it lives in.
  2. Task — the explicit instruction (verb-first).
  3. Constraints — must-not-do, format requirements, scope.
  4. Output format — schema, length, structure.
  5. Examples (few-shot when useful) — 1–3 ideal pairs.

Hyperparameters · the two PM dials

Temperature + length cap

Temperature

0 = deterministic-ish. 1+ = creative. Spec it for the job. Juno-as-risk-watchdog = low; Juno-as-brainstorm-partner = high.

Max tokens

Cap it. Long outputs hide failures. Short outputs force prioritisation.

Self-review checklist

Before you ship the system prompt

  • Persona names role + operating context?
  • Scope boundaries explicit ("only act on Slack escalations tagged P0")?
  • At least 3 guardrails, including 1 refusal rule?
  • Output format declared (markdown, schema, length cap)?
  • An example for the trickiest case?
The Optimization Decision Framework

Prompt → RAG → Fine-tune. Cheapest first.

LeverTry whenCost / time
PromptBehaviour needs tuning, not knowledgeMinutes. Almost free.
RAGYou need your data grounded (M3)Days. Real infra cost.
Fine-tuneStyle/format/behaviour at scale (last resort)Weeks. Training cost.

If you can fix it with the prompt, do not build infra.
