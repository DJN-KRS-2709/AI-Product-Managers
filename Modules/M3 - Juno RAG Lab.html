📥 Logic Ingestion Prompt
REQUIRED PLATFORM SETUP: - Enable Lovable Cloud for this project. - Use the built-in backend and AI model access. - Implement AI processing using a Supabase Edge Function. - Replace any mock or simulated AI outputs with real edge-function calls. Update my analyze-transcript edge function to support dual-mode analysis: Strategy Mode and Quality Mode. BEHAVIOR: 1. IF strategy document is provided -> STRATEGY MODE - The user's strategy document is the ONLY source of truth - Priority (P0-P3) based on explicit strategy document support - strategicPillar = the pillar name extracted from their document - strategicAlignment = how well the request aligns (0-100) - strategicRationale = explains why, citing the strategy document 2. IF no strategy document -> QUALITY MODE - Evaluate requests on REQUEST QUALITY SIGNALS instead - No strategic alignment possible without a strategy document - Priority based on how well-defined the request is QUALITY SIGNALS (for Quality Mode): | Signal | Points | |--------|--------| | Problem Clarity - Clear user problem vs solution-first | 0-25 | | Evidence Quality - Data/quotes vs assumptions | 0-25 | | Requirement Specificity - Estimable vs vague | 0-25 | | Anti-Pattern Check - Red flags absent? | 0-25 | QUALITY-BASED PRIORITY MAPPING: - 80-100 points -> P1 (High quality request) - 50-79 points -> P2 (Medium quality request) - 20-49 points -> P3 (Low quality request) - 0-19 points -> P3 + notRecommended For Quality Mode: - strategicPillar = descriptive category ("User Experience", "Reliability", "Growth", "Efficiency") - strategicAlignment = the Quality Score (0-100) - strategicRationale = explains quality assessment, notes "Without strategy document, priority reflects request quality, not strategic alignment" ANTI-PATTERNS (flag in BOTH modes): - Competitor-driven: "They have this, we need it" - Vanity/Optics: "Make it pop", "Show innovation" - Vague requirements: No clear user problem - Arbitrary deadlines: "Need it by Friday" without justification - Executive opinions without user evidence Set notRecommended: true for requests with multiple anti-patterns. EDGE FUNCTION REQUIREMENTS: - Accept { transcript: string, strategyDocument?: string } - strategyDocument is OPTIONAL - Return { insights: Insight[], prdContent: string } - Use appropriate system prompt based on whether strategy document exists - Tool schema should include all Insight fields including notRecommended PRD GENERATION: - With strategy: Group by strategic priority, cite strategy document - Without strategy: Group by quality score, include warning that this is quality-based prioritization
