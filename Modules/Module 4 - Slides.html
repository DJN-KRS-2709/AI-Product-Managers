Why AI-Native UX Matters

The 95%-accuracy-with-bad-UX product loses

You can have the best model, the cleanest RAG, the tightest evals — and still lose to a competitor whose UX:

  • Reveals reasoning when it matters
  • Surfaces confidence visually
  • Lets the user steer in one click
  • Gets out of the way when the AI is wrong

UX is where trust is built or destroyed. Spec it like a feature, not a polish task.

Speaker Notes

Reference Air Canada chatbot liability. UX failures become legal failures fast.
Designing Invisible UI for AI-Native Outcomes

Invisible by design

The default for AI-native UX. The system anticipates intent and acts at the right moment instead of waiting at a chat box.

Wrong

Juno is a chat tab in the sidebar. PM must remember it exists, open it, type a query.

Right

Juno surfaces a prioritised risk panel in Slack #escalations the moment a P0 thread crosses 5 messages. PM gets the answer before asking.

Speaker Notes

The right column is the principle. Anticipation > response. Visible only when value justifies attention.

How to Architect an AI User Flow

Architecting the AI Iceberg

Tip (what users see)

  • Trigger
  • Surface
  • Confirm / Correct

Underwater (what runs)

  • Capture context
  • Retrieve from corpus
  • Reason (model call)
  • Act (tool calls, writes)
  • Log (evals, traces)
  • Guardrail checks
  • Fallback paths

Most PMs design the tip and hand-wave the underwater. Spec both.

Speaker Notes

The underwater is engineering territory, but PMs spec what happens at each step (when to retrieve, what to log, what fallback). Don't skip it.
AI User Flow Example: HR Agent

Seven nodes per flow

  1. Trigger — what initiates the flow
  2. Capture — what context the system gathers
  3. Retrieve — what data is pulled in
  4. Reason — what the model decides
  5. Act — what happens in the world (send / write / call)
  6. Surface — what the user sees
  7. Confirm / Correct — how the user steers, accepts, overrides

The PM's Playbook for Closing AI Trust Gaps

Three trust gaps

GapQuestionMitigation
Black-boxCan the user see why?Reasoning, citations, "show your work"
HallucinationCould this confidently be wrong?Confidence cues, source links, escape hatches
ControlCan the user steer or stop?Undo, edit, regenerate, "don't suggest this again"

All three must be closed for a probabilistic system to feel safe.

Managing the Intelligence Tax

The extra latency or cognitive load is a product surface

  • Spec the maximum acceptable latency (p95).
  • Decide whether to stream output (perceived latency drops dramatically).
  • Decide whether to show "Juno is reasoning…" (transparency vs. distraction).
  • If the intelligence tax exceeds the value frame, kill the feature.

Speaker Notes

Streaming output is the cheapest perceived-latency improvement most learners overlook.

Self-review checklist

Before you ship the AI-UX work

  • The user flow names a real trigger (not "user opens app")
  • Each of the 7 nodes has one specific line
  • Tip vs. underwater is marked per node
  • All three trust gaps have an explicit mitigation
  • The intelligence tax is bounded (p95 + streaming on/off)
Key takeaways

What you carry into M5

  1. Chat-in-a-tab is the wrong default.
  2. Invisible by design — anticipate intent.
  3. Map value → UX treatment. Don't pick UX patterns by aesthetic.
  4. The AI Iceberg has 7 nodes. Spec all of them.
  5. Close all three trust gaps before shipping.
