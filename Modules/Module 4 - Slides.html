Lecture · Frame

Two ways to ship AI in a product

Both are valid. One bolts AI onto a workflow. The other is the workflow.
Traditional AI-UX
AI as a feature on a static UI
Approach

AI features retroactively layered on a deterministic workflow.

Interaction

User-driven — the user must manually trigger AI actions.

Outcome

Incremental efficiency without disrupting familiar habits.

Example

Google Search · AI Overviews — an AI summary block sits above the same 10-blue-link results page.

VS
AI-Native UX
The model is the workflow
Approach

Built from the ground up — the model is the engine, not a feature.

Interaction

Intent-driven — the interface evolves to surface only what’s needed.

Outcome

Seamless, personalized experiences. Minimal manual navigation.

Example

Perplexity — AI generates the answer; the list of links is gone.

Speaker Notes

Bing = traditional. Perplexity = AI-native. Both ship; one scales differently. The model isn't a feature in AI-native — it's the engine.

Framework

Why AI-Native UX matters

It’s not about better buttons. It’s about uncapping user potential by automating the manual execution that limits their impact.
📉
Lowered Interaction Costs

Move users from manual searching to reviewing and deciding.

🧠
Shifted Cognitive Load

Replace repetitive instructional labor with synthesis — freeing high-level judgment.

🔁
Increased System Resilience

Interface adapts to real intents instead of relying on rigid menus.

🎯
Contextual Relevance

Surface only the most relevant information and actions exactly when needed.

The shift: users move from builder to strategic reviewer. The product scales their judgment, not their typing.

Speaker Notes

Four reasons AI-native matters: lowered interaction costs, shifted cognitive load, system resilience, contextual relevance. Users move from builder → strategic reviewer.

Section 02
Designing Invisible UI for AI-Native Outcomes

Speaker Notes

Section 2 — three patterns + three placement maneuvers. Match value to surface.

Framework

Invisible by design — three patterns

Invisible isn’t about the AI disappearing. It’s about the labor disappearing.
🔌
Use environmental signals to trigger actions

Wake up on file uploads, meeting endings, page loads. Stop waiting for a manual prompt.

✨ Glean

Indexes activity in the background — analysis is done before you open the app.

💡
Leverage intent prediction to surface micro-UIs

Hide advanced controls until the system predicts the moment a user needs them.

✨ Adobe Firefly

“Generative Fill” bar appears only after you select an area in Photoshop.

🔀
Automate data flow between workflows

Push AI outputs directly into the next stage. Remove the friction of copy-paste.

✨ Salesforce

AI extracts a lead from a transcript and auto-maps to CRM fields + drafts the follow-up.

Speaker Notes

Three patterns: environmental signals (Glean), intent prediction (Adobe Firefly), automated data flow (Salesforce). Invisible = labour disappears, not the AI.

Framework

Choosing the AI interaction placement

Once you know the AI’s job, pick the real estate it deserves on the screen.
01
Inline & Embedded

AI capabilities placed directly in the text, code, or data the user is touching. Keeps them in flow.

✨ Google Docs

“Help me write” button moves with the cursor.

02
Floating & Contextual

Dynamic toolbars or hover menus that follow user selection. Tools appear only when contextually relevant.

✨ Figma AI

Floating pill appears at the bottom only when layers are selected.

03
Full-Page Canvas & Hubs

Dedicated views for high-complexity AI outputs. Roadmaps, decks, dashboards. Space to review V1 drafts.

✨ Gamma / Canva Magic

Generated decks open into a full-screen canvas for validation.

Speaker Notes

Three placements: Inline (Google Docs), Floating (Figma AI), Full-Page Canvas (Gamma/Canva). Choose by complexity of the AI output.

Lecture · Mental Model

Architecting the AI “Iceberg”

Don’t just map what the user does; map what the system thinks. The most powerful AI experiences are often the simplest UIs supported by the most complex background logic.

🖱️

Traditional mapping focuses on user clicks, screen navigation, and manual inputs.

🧠

AI-native mapping focuses on the background orchestration happening between a user’s intent and the final output.

💡
Top Tip

You must decide what remains “Invisible” to keep the experience effortless, and what needs to be “Visible” to build user trust.

PM lever: show too much of the underwater logic → cluttered UX. Show too little → lose user trust. You’re designing the balance between invisible effortlessness and visible verification.

Speaker Notes

Mental model: simple UI on top, complex logic below. The PM’s strategic lever is deciding the balance between effortlessness (invisible) and verification (visible).

Framework

The four architecture pillars

Each pillar has an underwater half (logic the PM specs) and a surface half (what the user feels).
01
The Trigger

Identify the earliest possible intent signal.

Underwater

📥 Meeting recording ends, PDF uploaded, page loads.

Surface

An ‘AI summary in progress’ notification appears instantly — before the user clicks anything.

02
The Processing State

Use the wait to build trust, not show a spinner.

Underwater

🔁 Routes the request, fetches data, reasons, drafts an output.

Surface

Breadcrumbs: “Scanning policy docs…” — turns latency into transparency.

03
The Presentation

Pick the maneuver that fits the value.

Underwater

🎯 Inline draft, floating overlay, or full-page canvas.

Surface

“V1 outreach email” renders directly in the message field.

04
The Feedback Loop

Every edit, undo, or accept is a training signal.

Underwater

🔁 Logs corrections back into the model state.

Surface

“Don’t use this tone again” updates the user’s tone profile.

Speaker Notes

Trigger / Processing / Presentation / Feedback Loop. Each pillar has an underwater half (PM specs the logic) and a surface half (what the user feels).

Section 04
The PM’s Playbook for Closing AI Trust Gaps

Speaker Notes

Section 4 — three failure modes (Black-box, Hallucination, Control) and the execution patterns that close each.

Trust Gap 1

The Black Box Gap

Users reject AI-generated insights when they can’t see the logic or the data sources used to reach the conclusion.
💡
Solution · Use explainable / controllable UI
  • Source scaffolding: Link AI summaries back to the original docs with inline citations or hover-states that show the source material.
  • Chain-of-thought visibility: Reveal reasoning steps for complex tasks — show files searched, rows extracted, decisions taken.
✨ Example · Perplexity
perplexity.ai
The Eiffel Tower is 330 m tall1 and was completed in 18892 after 2 years of construction3.
🔗 Sources
1 wikipedia.org 2 history.com 3 paris.fr

Dedicated Sources row + numbered citations throughout the answer — users verify any claim in a single click.

Speaker Notes

Source scaffolding + chain-of-thought visibility. The PM goal: reduce the cost of verification under 3 seconds. Perplexity is the gold-standard example.

Trust Gap 2

The Hallucination Gap

Users lose confidence in the entire product when the AI delivers factually incorrect or inconsistent answers without warning.
💡
Solution · Use explainable / controllable UI
  • Visual metadata: Use light-grey text, dotted underlines, or “Draft” watermarks where the model’s confidence score is below threshold.
  • Proactive caveats: Surface low-confidence warnings or alternative interpretations when the model is uncertain.
✨ Example · Gemini for Workspace
docs.google.com · gemini
Draft · Low confidence
Q4 revenue was approximately $4.2M based on preliminary estimates.
● “approximately $4.2M”
○ “around $4M”
○ “in the $4–5M range”
👍 👎 ↻ Regenerate

Draft watermarks for low-confidence output, plus rate / regenerate / pick another phrasing — turning probabilistic mistakes into a conversation.

Speaker Notes

Visual metadata + proactive caveats. Manage expectations, don’t pretend the model is certain. Gemini Workspace lets users rate, regenerate, and refine in-context.

Trust Gap 3

The Control Gap

Invisible design backfires when users feel locked in to an AI’s decision and can’t easily override, edit, or undo a mistake.
💡
Solution · Use explainable / controllable UI
  • One-click reversion: Provide instant undo or restore original for any AI-transformed content. Cost of a mistake = zero.
  • Direct-edit access: Never present AI output read-only. Every V1 draft must be instantly editable without a new prompt.
✨ Example · Midjourney · Vary Region
midjourney.com · image edit
✨ Vary Region
✏️ Vary Region
↶ Undo

Select a specific part of the AI image and re-generate just that section — surgical control instead of all-or-nothing.

Speaker Notes

One-click revert + direct edit. Never read-only. Midjourney’s Vary Region = surgical control instead of all-or-nothing regeneration.

Framework

The AI-UX Readiness Checklist

Don’t build “magic” on a broken foundation. Pass each level before climbing to the next.
01
Trigger Accuracy
Functional Baseline
Ship criterion

Does the AI trigger reliably at the correct moment?

Define strict confidence thresholds. Only automate when the system is ≥ 90% certain of intent.

02
System Transparency
Reliability & Verification
Ship criterion

Can the user verify the output in under three seconds?

Design source scaffolding — inline citations or logic summaries that bridge the trust gap without cluttering the UI.

03
Invisible Integration
Magical Flow
Ship criterion

Does the interaction remove more labor than it creates?

Measure correction rate. If users keep manually fixing the AI’s work, revert from invisible UI to a validator UI.

PM rule of thumb: if you can’t pass Level 2 yet, ship a Level-2 UI. A “reliable validator” product beats a “magical liar” product every time.

Speaker Notes

3-level hierarchy: Functional → Reliable → Magical. Don’t skip floors. If you can’t pass Level 2, ship a Level-2 UI — reliable validator > magical liar.

Lecture · Reality Check

Managing the “Intelligence Tax”

These aren’t bugs. They’re inherent properties of LLMs. Your UI hides the technical limits.
⏱️
Tax 01
The Latency Tax

High-quality model inference takes time. The user thinks the app is broken.

Manage with

Use streaming responses or status breadcrumbs (“Scanning backlog…”). Turn idle time into active progress.

🔐
Tax 02
The Privacy Tax

Users hesitate to share proprietary or personal data with a model they don’t own.

Manage with

Build permission-first architecture with clear privacy badges. Implement opt-in memory for surgical control.

Speaker Notes

Source slide 27. Two inherent LLM costs the UI must mask: Latency (streaming + status breadcrumbs turn waiting into transparency) and Privacy (permission-first + opt-in memory).

Key Takeaways

Design AI-Native User Experiences

AI-Native beats AI-Layered. Move from layering AI on legacy systems to designing flows where the model is the engine. Surface tools only when the system predicts intent.

Invisible UI uses environmental signals. Background tasks triggered by uploads, meetings, page loads. The user becomes a manager of outcomes, not an active operator.

Architect the AI Iceberg. Map underwater logic + visible maneuvers. Confidence thresholds and kill switches let users recover without friction.

Close trust gaps with explainable UI. Source scaffolding, chain-of-thought visibility, one-click undo. Verifiable in < 3 seconds or it doesn’t ship.
