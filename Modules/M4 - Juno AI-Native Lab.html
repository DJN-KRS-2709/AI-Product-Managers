Reimagine Juno as an AI-Native Copilot

Move Juno up the AI-UX Ladder — Functional Baseline (transparency) → Reliable (editable + verifiable) → Magical (invisible). Pick one path. Each level has a copy-ready Lovable prompt + a validation check. Optional. Not required for course completion.

Heads up · Lovable credits. Each level burns build credits. Free accounts get 2–3 prompts/day. Toggle on Chat mode to ask questions without burning credits, and refine your prompt in ChatGPT/Claude before pasting if needed.
Path 1 · Strategic Trust Ladder. You can’t scale judgment if you don’t trust the AI’s reasoning. Transform Juno from a system that “gives answers” into one that proves its work, cites its sources, and lets you surgically refine drafts.
1
Functional Baseline · Transparency
Force Juno to show its work

Stop the ‘Black Box’ effect. Add a Strategic Traceability footer to every Insight Card — rationale, source pillar badge, and a confidence meter.

📝 Level 1 Prompt
Refactor the InsightCard.tsx component to prioritize Transparency. 1. Add a new section at the bottom of the card titled "Strategic Traceability." 2. In this section, display the strategicRationale in a slightly smaller, italicized font. 3. If a strategicPillar is identified, wrap it in a "Source" badge that looks like a citation. 4. Add a visual "Confidence Meter" (a simple 5-bar sparkline) that maps to the strategicAlignment score (0-100). 5. Ensure this layout remains clean and doesn't break the existing 3-column grid.
Validation: Paste Artifact 1 (Sarah transcript) below + the RocketShip Strategy One-Pager into Juno. Click Process. Does Juno now cite specific pillars as “Proof”?
2
Reliability · Verification
Make the PRD modular & editable

The biggest complaint with AI PRDs is they’re “all or nothing.” Wrap each section in an EditableBlock + Regenerate button so the PM can refine surgically without rewriting the whole draft.

📝 Level 2 Prompt
Refactor the "Draft PRD" column (Right Column) to move from static text to a modular, editable workspace. Wrap each major section of the PRD (e.g., Problem Statement, Requirements, Risks) in an "EditableBlock" component. Each block should have an "Edit" icon that, when clicked, turns the text into a textarea for manual refinement. Add a "Regenerate" button (sparkle icon) to the top right of each block. This button should re-trigger the AI to rewrite only that specific section based on the original transcript, but with a more "concise" tone. Ensure the styling remains consistent with the dark-mode dashboard and that changes are saved to local state so they don't disappear if I click away.
Validation: Edit one requirement. Click Regenerate on just the “Risks” section. Does the “Problem Statement” stay exactly as you left it?
3
Magical · Invisible
Live-sync — Juno listens, thinks, synthesises

Remove the manual Process button. Add a 2500ms debounce on the transcript input. Show contextual status (“Juno is listening…” → “thinking…” → “synthesising…”) per column. Stream the PRD output character-by-character.

📝 Level 3 Prompt
Final Refactor: Transition Juno to a "Live-Sync" partner architecture with distributed, contextual feedback. 1. The Logic: Remove the "Process" button. Implement a 2500ms debounce on the Transcript Input. Create a global workflow state in Dashboard.tsx to track the phase: listening (typing), thinking (API fetching), processing (data received/streaming), and complete. 2. Column 1 (Transcript): At the bottom of the Transcript textarea, show "Juno is listening..." with a pulsing pulse icon only when the state is listening. 3. Column 2 (Insights): When the state moves to thinking, display "Juno is thinking..." with a pulsing brain icon animation in the center of the column. This must appear before the Insight cards fade in. 4. Column 3 (PRD): When the state is processing, display "Juno is synthesizing..." with a sparkles animation. Once the PRD text is ready, transition seamlessly into the character-by-character streaming effect. 5. Global Sync: Keep a simple "Synced" green checkmark in the header only when the state is complete. Ensure all loading skeletons are replaced by these contextual messages for a more "AI-native" feel.
Validation: Clear your transcript and start typing. Does the “Listening” status appear? When you stop, do the other columns “wake up” automatically?
Path 2 · Frictionless Architect. Your bottleneck is the admin tax of moving data between tools. Transform Juno from a dashboard that describes problems into a command center that executes solutions — logic-map highlighting, Slack/Jira launchers, and an invisible AI Risk Watchdog.
1
Functional Baseline · Transparency
Visual logic map — spatial proof

Trust isn’t just words; it’s spatial evidence. Add a Map icon on each Insight Card. On hover, highlight the source sentences in the transcript and the matching Strategic Pillar.

📝 Level 1 Prompt
Refactor the InsightCard.tsx to include a "Logic Map" feature for better transparency. 1. Add a small "Map" icon (lucide-react: map) in the top right of each card. 2. When a user hovers over this icon, trigger a "Connection Highlight" effect: - Temporarily highlight the specific sentences in the "Transcript Input" area that led to this insight in a subtle blue background. - Simultaneously highlight the specific "Strategic Pillar" badge in the Strategy column that this insight aligns with. 3. Add a tooltip to the Map icon that says: "Hover to see source connections." 4. Ensure this "Highlight" state is managed via a shared hoveredInsightId state in the parent Dashboard.tsx so all three columns can react to the hover event.
Validation: Add the RocketShip Strategy One-Pager + Artifact 1 below. Hover the Map icon — does it show exactly which transcript sentence triggered the insight?
2
Reliability · Verification
Slack & Jira command modals

Stop the copy-paste tax. Add a sticky Action Bar with Share to Slack + Create Jira Ticket modals. Each pre-fills with executive summary or PRD requirements, editable, then sends with a confirmation toast.

📝 Level 2 Prompt
Refactor the "Draft PRD" column to include a "Command Center" header for external actions. 1. Add a sticky "Action Bar" that is pinned to the top of the PRD Preview column, just below the column header. 2. Include two buttons with icons: "Share to Slack" (lucide-react: slack) and "Create Jira Ticket" (lucide-react: ticket). Give them a subtle border and hover effect to distinguish them from the PRD text. 3. When "Share to Slack" is clicked, open a Modal Overlay titled "Review Slack Summary." The AI should pre-fill this with a 2-sentence "Executive Summary" of the PRD. Make this text editable. 4. When "Create Jira Ticket" is clicked, open a Modal Overlay titled "Jira Ticket Draft." It should automatically extract the "Requirements" section from the PRD into the description field. 5. Each modal must have a "Confirm & Send" button that triggers a success Toast notification: "Draft sent to [Tool]." 6. Ensure the PRD content below this bar scrolls independently, so the Action Bar stays visible at all times.
Validation: Click Create Jira Ticket. Does the modal correctly extract the requirements from your draft?
3
Magical · Invisible
AI Risk Watchdog — the invisible flagger

Automate the critical-thinking step. Add a floating Risk Alert sidecar that slides in only when Juno detects high-risk assumptions (notRecommended insights or alignment < 30) and pre-drafts a mitigation Slack message.

📝 Level 3 Prompt
Final Refactor: Implement an "AI Risk Watchdog" that operates invisibly in the background. 1. Create a floating "Risk Alert" sidecar that slides out from the right side of the screen ONLY when the AI detects a high-risk assumption (e.g., technical debt or lack of evidence). 2. This sidecar should be titled "Juno's Risk Assessment" and feature a pulsing amber warning icon. 3. Add logic to the analyze-transcript function: if any insight is marked as notRecommended or has an alignment score below 30, automatically populate this sidecar with a "Mitigation Plan" (e.g., "Request Platform Team Review" or "Conduct User Interview"). 4. Include a "Quick Action" button inside the sidecar: "Draft Mitigation Slack Message." When clicked, it should use the "Share to Slack" modal logic to prepare a message to the relevant stakeholder. 5. The sidecar should have a "Dismiss" button, but it should re-appear if the user adds a new high-risk transcript entry. Ensure the transition is a smooth "slide-in" animation from the right.
Validation: Add a transcript with a clearly out-of-strategy ask. Does the sidecar slide in? Click Draft Mitigation Slack Message — does it pre-fill in the modal?
