The RAG Process

Retrieval-Augmented Generation in 4 steps

  1. Index — chunk, embed, store
  2. Retrieve — fetch relevant chunks for the query
  3. Augment — inject chunks into the prompt
  4. Generate — model responds, grounded

Reduces hallucination. Adds cost + latency. The trade-off is what to retrieve and when.

Architecture Decision Factors

Five questions to pick your RAG architecture

  1. Data freshness — how stale can context be?
  2. Corpus size — fits in context window vs. retrieve?
  3. Query latency budget
  4. Update cadence — read- or write-heavy?
  5. Privacy / tenancy

Tool: M3 - RAG Architecture Decider.html — answer the five questions, get a recommended architecture, export to your PRD.

Tokens and Context Windows

Bigger windows ≠ free

  • Context windows: 8k → 128k → 1M tokens
  • Cost per million tokens × usage = your AI margin line
  • Latency and "needle in a haystack" recall degrade with size

The 1M-token era changes the trade-off — it doesn't kill RAG.

Data Preparation

The PM corpus-readiness checklist

  • Source identification — which docs, channels, tickets?
  • Quality bar — freshness, accuracy, completeness
  • PII / sensitive-content handling
  • Permissions — does the corpus respect access?
  • Update cadence — how often does the index refresh?
