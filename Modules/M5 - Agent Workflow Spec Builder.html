Self-review · before you commit

  • Goal is one sentence and names the value frame.
  • Trigger is a precise, testable condition (not “when needed”).
  • Pattern is chosen with a defensible reason — ReAct unless you really need Planner-Executor.
  • At least 3 stop conditions (success / failure / escalation, plus a timeout).
  • Each memory type is named — including the “out of scope” ones.
  • Every tool lists scope (read-only vs write) and a schema.
  • Read/write boundaries match the access control in your AI PRD (M3).

A complete AWSpec broken into the four pillars. Read each block top-to-bottom — the same shape works for any agent. The HR Triage Agent mirrors the source slide-9 anatomy.

HR Triage Agent · Pillar 1 — Actors

Goal

Triage incoming HR requests into one of three lanes — policy question, vacation entry, escalate to HR business partner (Risk mitigation + cost reduction).

Trigger

Page-load on /hr-agent with a session token, OR new message in #hr-help from an employee.

Primary actor

Agent (autonomous) — the agent owns the routing decision. Employee is the user; HR business partner is the human-in-the-loop.

Humans in the loop

HRBP reviews any request the agent classifies as escalation. HRBP also reviews when classifier confidence < 75%.

HR Triage Agent · Pillar 2 — Pattern Plan

Pattern

ReAct — bounded sequential reasoning fits this scope; no parallel sub-tasks.

Sequential steps

1. Classify intent → question / task / escalation.
2. If question → RAG retrieval over HR-policy KB → cite policy.
3. If task → tool call to Workday API → submit vacation request.
4. If escalation → route to HRBP queue.
5. Log outcome + confidence to eval store.

Stop conditions

Success: response posted + confirmation rendered. Failure: 2 tool errors in a run → escalate. Confidence < 75% → escalate to HRBP. Timeout: 60s wall clock → abort.

HR Triage Agent · Pillar 3 — Memory

Episodic

In-scope — tool results within a single conversation. Lifetime: end of session.

Semantic

In-scope — HR taxonomy + system prompt. Out of scope — do NOT persist employee-specific compensation data.

Working / Contextual

Current request, user’s role, retrieved KB chunks. Held in working context only.

External tools

HR-policy KB (read), Workday API (write — vacation only), HRBP queue (write).

HR Triage Agent · Pillar 4 — Tools

Tool inventory

kb.retrieve(query, k=6) — read-only.
workday.submit_vacation(payload) — write, requires confidence ≥ 80%.
hrbp.escalate(payload) — write, no confidence gate.

Schemas

kb.retrieve → {chunks:[{text,source,section,score}]}. workday.submit_vacation → {request_id, status}.

Read / write boundaries

Agent can READ the HR handbook and KB. Agent can WRITE to Workday (vacation submissions) and HRBP queue. Agent CANNOT edit payroll, edit benefits, or read compensation data.

PM takeaway: the AWSpec is just four blocks. The rigour is in the specifics — precise triggers, named patterns, scoped tools. Apply the same template to Juno.
